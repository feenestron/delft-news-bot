# Delft News Bot

Telegram-бот, который каждое утро собирает местные новости и анонсы мероприятий Делфта,
переводит и сокращает их на русский (через Claude API) и сразу публикует дайджест
в группу (или канал). Без модерации — так же, как бот выставок.

Работает целиком на GitHub Actions — сервер не нужен.

```
06:20  cron-job.org запускает workflow в GitHub Actions
  ↓    бот собирает новости и афишу
  ↓    Claude отбирает, переводит, сокращает
  →    дайджест публикуется в группу; вам в личку — только если что-то не так
```

## Пример поста

> **🗞 Делфт · четверг, 22 октября**
>
> **📰 События**
> • **Крупный пожар в центре удалось локализовать** — Эвакуированы жители десяти домов. [Omroep Delft]
> • …
>
> **📅 Анонсы**
> • **сб 24 окт, 20:15** · Tim Burton's Universe (Nieuwe Kerk, €25) →
> • **вс 25 окт, 11:00–17:00** · День науки в TU Delft (TU Delft Science Centre, бесплатно) →

## Настройка (один раз, ~15 минут)

### 1. Бот и группа
1. В Telegram откройте **@BotFather** → `/newbot`, придумайте имя. Сохраните **токен**.
2. Добавьте бота в группу (или канал) — если писать там могут только админы,
   сделайте бота **администратором**.
3. Откройте личный чат со своим ботом и нажмите **Start** — туда бот пишет о проблемах.

### 2. Ключ Claude API
На [console.anthropic.com](https://console.anthropic.com) создайте API-ключ и пополните баланс
(дайджест стоит порядка нескольких центов в день). Без ключа бот тоже работает,
но заголовки будут на нидерландском без перевода.

### 3. Секреты в GitHub
Репозиторий → **Settings → Secrets and variables → Actions → New repository secret**:

| Секрет | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от BotFather |
| `CHANNEL_ID` | id группы (`-100…`, см. шаг 4) или `@имя_канала` |
| `ANTHROPIC_API_KEY` | ключ Claude API |
| `ADMIN_CHAT_ID` | *необязательно*: ваш личный chat_id — туда бот пишет о сбоях и проблемах с источниками |

### 4. Узнать id группы
Добавьте бота в группу (если он уже там — удалите и добавьте снова), напишите в группе
любое сообщение и запустите **Actions → Find chat id → Run workflow**. В Summary запуска
будет список групп с их id — значение для `CHANNEL_ID`.

### 5. Проверка
**Actions → Daily digest → Run workflow** — по умолчанию отмечен **dry_run**: дайджест
появится в Summary запуска и в `preview/last_dry_run.md`, в Telegram ничего не уйдёт.
Чтобы опубликовать прямо сейчас, снимите dry_run и отметьте **force**.

## Когда бот пишет вам в личку

Только если что-то пошло не так (в `ADMIN_CHAT_ID`):
* сломался источник или не сработал перевод — дайджест всё равно публикуется, а вам
  приходит список проблем;
* новых материалов нет — в группу ничего не отправлено;
* публикация не удалась (бота убрали из группы, нет прав и т. п.) — с причиной,
  плюс ссылка на лог запуска.

## Настройки (необязательно)

**Settings → Secrets and variables → Actions → Variables**:

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `POST_HOUR` | `6` | с какого часа (по Амстердаму) можно публиковать |
| `POST_UNTIL_HOUR` | `12` | до какого часа ещё публиковать, если запуск опоздал |
| `NEWS_WINDOW_HOURS` | `30` | насколько свежими должны быть новости |
| `EVENT_HORIZON_DAYS` | `3` | на сколько дней вперёд брать анонсы |
| `MAX_NEWS` / `MAX_EVENTS` | `8` / `8` | максимум пунктов в разделах |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | модель Claude |

Если меняете `POST_HOUR`, поправьте время в cron-job.org (и резервный cron в
`.github/workflows/digest.yml`).

## Источники

Список — в [`sources.yaml`](sources.yaml); источник можно добавить или отключить
(`enabled: false`) без правки кода.

| Новости | Афиша |
|---|---|
| Omroep Delft (RSS) | Uit Delft (JSON API) |
| Delft op Zondag | Delft op Zondag — агенда |
| Gemeente Delft | OPEN Delft / DOK (выключен: дублирует Uit Delft) |
| Delta, TU Delft (RSS) | In Delft — Uitagenda |

Бот соблюдает `robots.txt`, представляется отдельным User-Agent и заходит на каждый
сайт один раз в день. Если источник сломался (сменили вёрстку), бот напишет об этом
вам в личку, а дайджест выйдет из остальных источников.

Как бот понимает, что новое:
* новости — по дате публикации и списку уже увиденных ссылок; при первом запуске
  источника всё, что уже висит на странице без даты, считается старым;
* анонсы — по дате события (из API, из ссылки или со страницы); каждое событие
  анонсируется один раз.

Состояние хранится в `state/state.json` и коммитится workflow автоматически.

## Локальный запуск

```bash
pip install -r requirements.txt
python -m bot digest --dry-run          # собрать и напечатать, ничего не отправлять
python -m unittest discover -s tests    # тесты
```

## Эксплуатация

* **Сбои.** Если запуск упал, бот пишет причину в `ADMIN_CHAT_ID`, а workflow — ссылку на лог.
* **Пропущенный запуск.** Публикация происходит при первом запуске между `POST_HOUR` и
  `POST_UNTIL_HOUR`; повторные запуски в тот же день ничего не дублируют.
* **Автоотключение расписания.** GitHub отключает cron в публичных репозиториях после 60 дней
  без активности; каждый утренний запуск заново включает резервное расписание.
* **Модель Claude.** Если Anthropic выведет модель из оборота, бот напишет об ошибке перевода —
  укажите новую модель в переменной `ANTHROPIC_MODEL`.
* **Смена группы/канала.** Добавьте бота в новый чат, запустите **Find chat id** и обновите
  секрет `CHANNEL_ID`.
* **Токен для cron-job.org** истекает — перевыпустите его заранее и обновите в cronjob.

## Надёжный утренний запуск (cron-job.org)

Расписание GitHub Actions работает «по возможности»: запуски опаздывают на час и больше,
а иногда пропускаются совсем. Встроенное расписание оставлено как резерв, а основной
триггер — бесплатный внешний планировщик, который каждое утро «толкает» workflow.

1. **Токен GitHub.** github.com → Settings → Developer settings → Personal access tokens →
   **Fine-grained tokens → Generate new token**:
   * Repository access → *Only select repositories* → `delft-news-bot`;
   * Permissions → Repository permissions → **Contents: Read and write**
     (нужно для события `repository_dispatch`);
   * Expiration — максимальный срок; поставьте напоминание продлить.
2. **cron-job.org** → зарегистрироваться → **Create cronjob**:
   * URL: `https://api.github.com/repos/feenestron/delft-news-bot/dispatches`
   * Schedule: каждый день в **06:20**, часовой пояс **Europe/Amsterdam**
     (и, по желанию, второй запуск в 06:50 — повтор ничего не задублирует);
   * Advanced → Request method **POST**, Headers:
     * `Authorization: Bearer <токен из шага 1>`
     * `Accept: application/vnd.github+json`
     * `Content-Type: application/json`
   * Request body: `{"event_type": "daily-digest"}`
3. Нажмите **Test run** — ответ должен быть `204`, а в Actions появится запуск
   «Daily digest». Если дайджест за сегодня уже был, запуск просто завершится.

## Как отбираются новости

Claude оценивает **каждую** найденную новость и ставит уровень:

* **обязательно** — влияет на быт жителей: закрытия и сбои городских служб, перекрытия и ремонт улиц,
  забастовки и сбои транспорта, происшествия и предупреждения полиции, сроки для жителей, изменения
  цен, налогов, тарифов и правил. Такие новости попадают в пост **всегда, без лимита**;
* **интересно** — культура, массовые мероприятия, здоровье, городская жизнь. Лучшие — до лимита `MAX_NEWS`
  (не меньше трёх, даже если обязательных много);
* **не брать** — с короткой причиной («не в Делфте», «колонка», «дубликат»…).

Страховочная сетка: если в новости есть слова вроде *dicht, gesloten, storing, afgesloten, omleiding,
staking, waarschuwing, werkzaamheden, deadline…*, а Claude её не взял, она всё равно попадает в пост
строкой «Возможно, важно».

Анонсы оцениваются так же: **стоит внимания** (крупные концерты и спектакли в больших залах, фестивали,
ярмарки, городские праздники, значимые выставки, лекции известных людей, спорт городского масштаба,
фестивальное кино; из церковных — только большие праздники вроде Пасхи) идут первыми, **можно** — на
оставшиеся места, **не брать** — всё детское и школьное, местные группы в барах, open mic и DJ-вечера,
обычные церковные службы, рутина, события не в Делфте.

Отбор предсказуемый (temperature 0, стабильный порядок кандидатов). Всё, что не вошло, с причинами
видно в Summary запуска и в `state/latest.json` (поля `skipped` и `skipped_events`).

## Архив дайджестов в JSON

После каждой публикации бот сохраняет тот же дайджест в `state/latest.json` и
`state/digests/ГГГГ-ММ-ДД.json` (последние 7 выпусков, список — `state/digests/index.json`).
Их читает, например, виджет «Новости Делфта» на домашней странице: файлы доступны по адресу
`https://raw.githubusercontent.com/feenestron/delft-news-bot/main/state/latest.json`.
